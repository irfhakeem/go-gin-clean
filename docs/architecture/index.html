Level 2 — Containers & Runtime Processes

Level 2: Containers & Runtime Processes

Zooms into the deployable containers (docker-compose.yml and Dockerfile) and the concurrent runtime goroutines inside the cmd/server binary. It illustrates how Gin HTTP Server, Outbox Worker (polling PostgreSQL every 5s with FOR UPDATE SKIP LOCKED in internal/delivery/worker), and Consumer Worker (AMQP QoS=1 with retry/DLX queues) coordinate via PostgreSQL 16, Redis 7 Alpine, and RabbitMQ 3, alongside the standalone Migration CLI (cmd/migrate).

Level 4 — Code / Runtime Sequence Flows

Level 4A: Register & Transactional Outbox Runtime Flow

Traces POST /api/v1/auth/register from AuthHandler.Register into authUseCase.Register and gormTxManager.WithTx, showing how userRepo.Create(txCtx) and outboxRepo.Create(txCtx) commit atomically in one PostgreSQL transaction. Then traces the asynchronous OutboxWorker polling loop, publisher.Publish("user.register"), and EmailEventHandler.HandleUserVerifyEmail sending the verification email via SMTP.

Level 4B: Login & Atomic Refresh Token Rotation Flow

Traces POST /api/v1/auth/login and POST /api/v1/auth/refresh-token through AuthHandler, authUseCase, JWTMaker, AESEncryptor, and PostgresRefreshTokenRepository. Shows how refresh tokens are AES-256-GCM encrypted before storage and how token rotation wraps RevokeByToken(txCtx) and Save(txCtx) in a single WithTx transaction so a failed save rolls back revocation.

Level 4C: Two-Tier RBAC & Redis Cache-Aside User Flow

Traces GET /api/v1/users through Tier 1 middleware (AuthMiddleware.RequireAuth and RequireRole(UserRead)) and Tier 2 domain policy scoping (UserPolicy.Scope inside userUseCase.GetAllUsers).
